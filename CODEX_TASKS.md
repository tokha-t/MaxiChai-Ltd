## Задача 1 — каркас интерфейса и список диалогов

```
Прочитай AGENTS.md и server/app.py. Сделай интерфейс в папке web/ (index.html, css/styles.css, js/app.js, js/api.js, js/views/*.js).
Только HTML/CSS/vanilla JS (ES-модули), без сборки и без CDN.

1. Каркас: шапка «CQA · Контроль качества диалогов», меню: Диалоги, Апелляции, Чек-лист, Дашборд.
   Справа в шапке переключатель роли «Оператор / Проверяющий» (без авторизации, хранить в памяти и в URL-параметре role).
   Роутинг через hash: #/dialogs, #/dialog/<id>, #/checklist, #/appeals, #/dashboard. По умолчанию #/dialogs.
   Если в URL есть ?conversationId=..., сразу открыть карточку диалога.
2. js/api.js — единственное место с fetch. База: window.CQA_API_BASE || "". Ошибки сервера (detail) показывать тостом.
3. Экран «Диалоги» (GET /api/conversations): таблица — ID, канал (иконка чат/звонок), язык, итог (крупно; если итог после апелляций отличается от оценки ИИ — показать «ИИ 85 → 90»), бейдж «Грубая ошибка» (красный), значок ⚠ «нужна проверка» (needs_review), число открытых апелляций, версия чек-листа, дата оценки. Неоценённые — серым «не оценён».
   Фильтры над таблицей: группа (GET /api/groups), язык, канал, «только грубые ошибки», «только ⚠», поиск по ID. Фильтры работают через query-параметры API.
   Клик по строке → #/dialog/<id>.
4. Дизайн: светлая тема, акцентный зелёный #00A36C, шрифт system-ui, аккуратные таблицы, адаптивно до 1024px. Без внешних шрифтов.

Готово, когда: список DEV-диалогов виден, фильтры работают, клик открывает пустую пока карточку.
```

## Задача 2 — карточка диалога: транскрипт, оценка, переход к реплике

```
Экран #/dialog/<id> (GET /api/conversations/<id>). Две колонки.

Слева — транскрипт: каждая реплика с номером [n], временем rel и ролью (Клиент / Оператор / Бот / Система, разные цвета;
бот и система приглушены). Реплики внутри facts.hold_ranges пометить «удержание: внутренняя консультация».
У каждой реплики id="turn-<n>".

Справа — оценка (evaluation):
- Итог крупно: final.score.final_score из 100. Рядом «оценка ИИ: ai_score.final_score», если отличается.
- Если final.score.critical_flag — красный баннер «Грубая ошибка» с обоснованием критерия critical и ссылками на реплики.
- Баллы по секциям (score.sections: name, score, earned/max).
- Карточка на каждый критерий из final.criteria: название, секция, бейдж значения (value_label: Да зелёный, Нет красный,
  N/A серый, шкала «15 из 20»), баллы points из max_points, вес и вес после перераспределения (effective_weight),
  обоснование rationale, чипы реплик evidence_turns. Для «Нет» подпись «проверенный участок», для N/A — «почему неприменим».
  Индикатор согласия голосов: agreement (например, «3/3 прогона согласны»), значок ⚠ если needs_review.
  Если критерий изменён апелляцией (overridden) — показать «ИИ: … → решение проверяющего: …».
- Клик по чипу реплики: плавно прокрутить транскрипт к #turn-<n> и подсветить её на 2 секунды.
- Внизу: модель, версия чек-листа, стоимость usage.cost_usd ($), время usage.latency_sec, число вызовов, дата.
- Сворачиваемый блок «Факты, посчитанные кодом»: первая реакция (секунды и порог), долгие паузы, подтверждение личности,
  закрытие чата/уход клиента.
- Кнопка «Переоценить» → POST /api/evaluate {conversation_ids:[id]} и опрос GET /api/jobs/<job_id> раз в секунду
  с прогресс-баром, затем перерисовать карточку.
- История оценок (history) — компактный список.

Готово, когда: в карточке видны баллы, обоснования и переход к реплике по клику.
```

## Задача 3 — загрузка данных и запуск оценки

```
На экране «Диалоги»:
1. Кнопка «Загрузить набор из API»: поле group_id (по умолчанию DEV) → POST /api/datasets/fetch {group_id}. Показать сколько загружено.
2. Кнопка «Добавить диалог»: модальное окно с двумя вкладками:
   a) «JSON» — вставка JSON (ответ API организаторов, массив записей или одна запись) → POST /api/conversations/upload {group_id, payload};
   b) «Текст» — textarea, строки вида «[00:15] Клиент: …», «Оператор: …», поля ID, канал, язык → POST /api/conversations/upload {text, conversation_id, channel, language}.
   После загрузки предложить «Оценить сейчас».
3. Чекбоксы в таблице + кнопки «Оценить выбранные» и «Оценить всю группу» → POST /api/evaluate.
   Прогресс-бар: опрос GET /api/jobs/<job_id> (done/total, стоимость cost_usd, число вызовов llm_calls, прошедшее время).
   По завершении — обновить таблицу. Во время задачи кнопки неактивны.
4. Кнопка «Экспорт results.json» → скачивание GET /api/export?group_id=<группа>.

Готово, когда: можно вставить новый диалог текстом, оценить его и увидеть результат в карточке.
```

## Задача 4 — апелляции

```
1. В карточке диалога у каждого критерия кнопка «Оспорить» (видна в роли «Оператор»): модальное окно с исходной оценкой
   и полем комментария → POST /api/appeals {evaluation_id, criterion_id, comment, author}. После создания у критерия
   бейдж «Апелляция на рассмотрении».
2. Экран #/appeals (для роли «Проверяющий»), вкладки «Открытые» / «Рассмотренные» (GET /api/appeals?status=open и без фильтра).
   Карточка апелляции: диалог (ссылка), критерий, исходная оценка (original_label) и обоснование ИИ, комментарий оператора,
   фрагмент диалога (fragment — реплики с номерами; реплики из evidence_turns подсветить),
   «Второе мнение ИИ» (ai_review: recommendation keep/change, suggested_label, rationale; если ещё null — «готовится…»
   и автообновление раз в 3 секунды; кнопка «Запросить заново» → POST /api/appeals/<id>/ai-review).
3. Форма решения: «Подтвердить оценку» или «Изменить оценку» + выбор нового значения по типу критерия
   (binary: Да/Нет и N/A, если criterion.na_allowed; scale: ступени из criterion.scale и N/A, если разрешён; flag: Да/Нет),
   причина (обязательна) → POST /api/appeals/<id>/decision {decision: "confirmed"|"changed", value, reason, reviewer}.
   После решения показать: исходная оценка → решение → итог ai_final_score → final_score.
4. В карточке диалога блок «Апелляции»: исходная оценка, решение, причина, итог после пересмотра.

Готово, когда: можно оспорить критерий, принять решение в роли проверяющего и увидеть новый итог в карточке.
```

## Задача 5 — редактор чек-листа и применение

```
Экран #/checklist.
1. Слева список версий (GET /api/checklists): версия, заметка, дата, активная отмечена. Кнопка «Сделать активной» → POST /api/checklists/<id>/activate.
2. Справа редактор активной версии (GET /api/checklists/active; поля, начинающиеся с «_», не отправлять обратно):
   - название, порог первой реакции (first_response_threshold_sec), общие правила (notes);
   - секции (id, name) — добавить/удалить;
   - критерии карточками: id, название, секция (select), тип (Да/Нет — binary, Шкала — scale, Грубая ошибка — flag),
     вес (для flag скрыт), «Разрешить N/A» + условие N/A, формулировка (description), для шкалы — ступени (значение + описание,
     добавить/удалить), «Подсказки для ИИ» (guidance, большой textarea);
   - добавить критерий, удалить, поднять/опустить;
   - сумма весов наверху (POST /api/checklists/validate возвращает errors и weights_sum) и список ошибок в реальном времени.
3. «Сохранить как новую версию» (поле «что поменяли») → POST /api/checklists {data, note, activate: true}.
4. После сохранения кнопка «Применить к диалогам»: выбор группы или «все» → POST /api/evaluate {group_id, checklist_id} с прогрессом.
   Подсказка: неизменённые критерии переиспользуются, изменение веса пересчитывается без модели, перегоняются только изменённые формулировки.
5. После применения — таблица «Что изменилось» (GET /api/diff?group_id=..&from_checklist=<прошлая>&to_checklist=<новая>):
   диалог, итог до → после, изменённые критерии.

Готово, когда: можно заменить формулировку одного критерия, сохранить, применить к группе и увидеть разницу за секунды.
```

## Задача 6 — дашборд и «грубые ошибки»

```
Экран #/dashboard (GET /api/stats?group_id=...):
- плитки: оценено диалогов, средний итог, с грубыми ошибками (клик → #/dialogs с фильтром «только грубые ошибки»),
  требуют проверки ⚠, открытые апелляции, средняя стоимость одной оценки ($) и модель;

Плюс на экране «Диалоги» кнопка-фильтр «Грубые ошибки» и в таблице под бейджем короткое пояснение: тип нарушения из rationale критерия critical.

Готово, когда: по одному клику видны все диалоги с грубыми ошибками и объяснения.
```
